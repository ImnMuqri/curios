# Slice 6 — FAQ pages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn a question an owner has answered, and strangers keep asking, into a public page Google can index.

**Architecture:** A pure rule in `packages/core` decides which questions qualify. `apps/api` stamps a stored `faqSlug` onto qualifying questions from the two places that already write — the answer-writeback and the chat path's question logging — because `apps/web` holds a SELECT-only connection and cannot mint one on read. `packages/db-read` gains two gated queries, and two new Next routes render them with `FAQPage` structured data under a 24h ISR window.

**Tech Stack:** TypeScript, Prisma 6, Fastify 5, Next 15 (App Router, RSC), vitest, Postgres.

**Spec:** `devDocs/slice-6-build-spec.md` — read it before Task 1. This plan argues from it.

## Global Constraints

- The qualifying rule is exactly: `mode === 'BUSINESS' && askCount >= 3 && answered`. All three, no exceptions, one implementation.
- `FAQ_MIN_ASKS = 3`. A named constant in `packages/core`, not an env var — it is a product rule, not deployment config.
- `faqSlug` is **stored** and never recomputed on read. Once assigned it is never overwritten and never cleared, including when a pinned answer is deleted. A URL that has begun to rank must not move.
- Both FAQ routes: `export const runtime = 'nodejs'` and `export const revalidate = 86400`. **No `generateStaticParams` anywhere** — it would make `pnpm build` require a live database, which it currently does not.
- Every JSON-LD payload goes through `serialiseJsonLd`. Never `JSON.stringify` into a script element directly.
- Slug assignment is **best-effort**: a failure logs and returns, never propagates. It sits inside a visitor's chat request and an owner's answer request, and neither may fail because an SEO page could not be named.
- All four read gates (`published`, `mode === 'BUSINESS'`, `faqSlug` present, `PinnedAnswer` exists) live in `packages/db-read`, never in a route.
- Any new `.module.css` under `apps/web/app` is walked by `packages/ui/src/design-rules.test.ts`. No hex literals anywhere but `tokens.css`, and `font-size` only from the six declared steps: `--text-xs` 11px, `--text-sm` 12.5px, `--text-base` 14px, `--text-body` 17px, `--text-lg` 22px, `--text-display` 32px. Write the token reference, not the pixel value. There is no `--rule` token; dividers use `var(--surface)`.
- Test commands: `pnpm turbo run test --concurrency=1` for the workspace. Never `pnpm turbo run test` without `--concurrency=1` — the DB-touching packages share one test database and truncate `"Account" CASCADE`, so running them in parallel makes them wipe each other's fixtures and produces failures that move between packages.

Create `packages/core/src/faq.ts`:

```ts
/**
 * BACKEND.md: "do not generate FAQ pages for questions nobody asked, that is
 * content farm behaviour and it will read as one."
 *
 * Three, not one: one ask is somebody asking, but a page per stray question is
 * a hundred thin pages, which is the shape of the thing that rule forbids.
 * Three, not five: these are small shops, and a threshold that generates
 * nothing for two months is a feature that dies before anyone sees it work.
 */
export const FAQ_MIN_ASKS = 3;

/** Long enough to stay readable, short enough for a sane URL. */
const SLUG_MAX = 60;

/**
 * Whether a question may become a public page.
 *
 * Deterministic and in one place, the same argument `qualifies` settled for
 * lead capture in slice 4: a rule you can unit-test in a function beats a rule
 * you tune in a prompt or a config table.
 *
 * `askCount` and `answered` are not redundant. The count is evidence of
 * demand, `answered` is evidence that the owner wrote the words themselves,
 * and a public page wants both.
 */
export function qualifiesForFaq(input: {
  mode: 'PERSONAL' | 'BUSINESS';
  askCount: number;
  answered: boolean;
}): boolean {
  if (input.mode !== 'BUSINESS') return false;
  if (input.askCount < FAQ_MIN_ASKS) return false;
  return input.answered;
}

/**
 * The slug for a question, before any collision suffix.
 *
 * `\p{L}` rather than `[a-z]`: Malay is Latin script and survives either way,
 * but the ask bar takes any language and a slug of empty segments is worse
 * than a slug with a non-ASCII letter in it.
 *
 * Null, not '', when nothing survives. An empty slug written to the column
 * would be a unique value that resolves to a route rendering nothing, and the
 * caller must be forced to notice.
 */
export function faqSlugBase(questionText: string): string | null {
  const slug = questionText
    .normalize('NFKC')
    .toLowerCase()
    .replace(/[^\p{L}\p{N}]+/gu, '-')
    .replace(/^-+|-+$/g, '')
    .slice(0, SLUG_MAX)
    // Slicing can leave a trailing separator where it cut mid-separator.
    .replace(/-+$/g, '');

  return slug.length > 0 ? slug : null;
}

/**
 * A JSON-LD payload safe to place inside a script element.
 *
 * `JSON.stringify` escapes quotes and backslashes and leaves `<` alone,
 * because `<` is legal inside a JSON string. That is enough for an answer
 * containing a closing script tag to end the element early and have everything
 * after it parsed as HTML -- script injection into a public page, reachable by
 * any owner who can write an answer.
 *
 * Escaping `<` to its unicode form is still valid JSON and parses back to the
 * identical object, so nothing is lost but the ability to close a tag.
 *
 * One function that does both steps, so no caller can serialise and forget to
 * escape.
 */
export function serialiseJsonLd(payload: unknown): string {
  return JSON.stringify(payload).replace(/</g, '\\u003c');
}
```

Create `apps/api/src/modules/questions/faq-slug.ts`:

```ts
import { faqSlugBase, qualifiesForFaq } from '@curios/core';
import type { PrismaClient } from '@curios/db';

/** How many suffixed names to try before giving up on a slug. */
const MAX_ATTEMPTS = 20;

interface Log {
  error: (obj: unknown, msg: string) => void;
}

/**
 * Give a question its public URL, if it has earned one.
 *
 * Called from BOTH places that can complete the rule, because either condition
 * can be the last to arrive: the owner writing an answer, or a third visitor
 * asking. Wire only one and FAQ pages appear for some questions and never for
 * others, decided by the order an owner and a stranger happened to act -- a
 * bug that reads as randomness.
 *
 * Idempotent and best-effort. It re-runs on every ask and every answer edit
 * for the life of a question, so doing nothing must be cheap and safe; and it
 * sits inside a visitor's chat request, so no failure here may become their
 * error. Everything is caught and logged.
 */
export async function assignFaqSlug(
  prisma: PrismaClient,
  questionId: string,
  log?: Log,
): Promise<void> {
  try {
    const question = await prisma.question.findUnique({
      where: { id: questionId },
      select: {
        id: true,
        pageId: true,
        text: true,
        askCount: true,
        answered: true,
        faqSlug: true,
        page: { select: { mode: true } },
      },
    });

    // Gone, or already named. Both are ordinary, and neither is an error.
    if (!question || question.faqSlug !== null) return;

    if (
      !qualifiesForFaq({
        mode: question.page.mode,
        askCount: question.askCount,
        answered: question.answered,
      })
    ) {
      return;
    }

    const base = faqSlugBase(question.text);
    if (base === null) {
      log?.error({ questionId }, 'question has no sluggable text; no faq url assigned');
      return;
    }

    // Read the taken names rather than guessing, then let the unique
    // constraint be the final arbiter -- two concurrent asks can both read
    // "free" and only one write can win.
    const taken = new Set(
      (
        await prisma.question.findMany({
          where: { pageId: question.pageId, faqSlug: { startsWith: base } },
          select: { faqSlug: true },
        })
      ).map((row) => row.faqSlug),
    );

    for (let attempt = 1; attempt <= MAX_ATTEMPTS; attempt++) {
      const candidate = attempt === 1 ? base : `${base}-${attempt}`;
      if (taken.has(candidate)) continue;
      try {
        await prisma.question.update({
          where: { id: question.id },
          data: { faqSlug: candidate },
        });
        return;
      } catch {
        // Almost certainly P2002 from a concurrent assignment. Try the next
        // name rather than inspecting the error code -- every other failure
        // here is also "could not take this name".
        taken.add(candidate);
      }
    }

    log?.error({ questionId, base }, 'could not find a free faq slug');
  } catch (error) {
    // The outer guard. An SEO URL is never worth failing a visitor's chat or
    // an owner's answer.
    log?.error({ err: error, questionId }, 'faq slug assignment failed');
  }
}
```

```ts
import { prismaRead } from './client.js';

export interface FaqListEntry {
  slug: string;
  question: string;
}

export interface FaqIndex {
  handle: string;
  displayName: string;
  entries: FaqListEntry[];
}

export interface FaqAnswer {
  handle: string;
  displayName: string;
  question: string;
  answer: string;
}

/** Enough for any real page; a bound so one owner cannot make a huge document. */
const DEFAULT_LIMIT = 50;
const MAX_LIMIT = 200;

/**
 * Where the page's own gates live, so no route can forget one.
 *
 * `findFirst`, not `findUnique`: the handle is unique but `mode` is not part of
 * any unique index, and all three conditions have to be in the same query.
 */
function publishedBusinessPage(handle: string) {
  return prismaRead.page.findFirst({
    where: { handle: handle.toLowerCase(), published: true, mode: 'BUSINESS' },
    select: { id: true, handle: true, displayName: true },
  });
}

/**
 * Every question on a page that has earned a public URL and still has an
 * answer behind it, most asked first.
 *
 * Two queries rather than a join: `Question` and `PinnedAnswer` have no Prisma
 * relation, but both carry a unique `(pageId, normalizedQuestion)`, so this is
 * two indexed reads and an in-memory match -- no raw SQL, and no new foreign
 * key on a table the chat path writes to on every question.
 *
 * The answer is read through `PinnedAnswer` rather than cached onto `Question`
 * so that withdrawing an answer removes the page on the next render, without
 * anyone having to remember a second write.
 */
export async function getFaqIndex(
  handle: string,
  options: { limit?: number } = {},
): Promise<FaqIndex | null> {
  const page = await publishedBusinessPage(handle);
  if (!page) return null;

  const questions = await prismaRead.question.findMany({
    where: { pageId: page.id, faqSlug: { not: null } },
    orderBy: [{ askCount: 'desc' }, { lastAskedAt: 'desc' }],
    take: Math.min(options.limit ?? DEFAULT_LIMIT, MAX_LIMIT),
    select: { faqSlug: true, text: true, normalizedQuestion: true },
  });

  const answered = new Set(
    (
      await prismaRead.pinnedAnswer.findMany({
        where: {
          pageId: page.id,
          normalizedQuestion: { in: questions.map((q) => q.normalizedQuestion) },
        },
        select: { normalizedQuestion: true },
      })
    ).map((row) => row.normalizedQuestion),
  );

  return {
    handle: page.handle,
    displayName: page.displayName,
    entries: questions
      .filter((q) => answered.has(q.normalizedQuestion))
      // The slug is non-null by the query above; this narrows it for the type.
      .map((q) => ({ slug: q.faqSlug as string, question: q.text })),
  };
}

/**
 * One question and the owner's exact words.
 *
 * Null covers every failure the route turns into a 404: no such handle, a
 * personal page, an unpublished page, a slug nobody holds, and a slug whose
 * answer has been withdrawn. The route does not need to tell them apart.
 */
export async function getFaqEntry(handle: string, slug: string): Promise<FaqAnswer | null> {
  const page = await publishedBusinessPage(handle);
  if (!page) return null;

  const question = await prismaRead.question.findFirst({
    where: { pageId: page.id, faqSlug: slug },
    select: { text: true, normalizedQuestion: true },
  });
  if (!question) return null;

  const pinned = await prismaRead.pinnedAnswer.findUnique({
    where: {
      pageId_normalizedQuestion: {
        pageId: page.id,
        normalizedQuestion: question.normalizedQuestion,
      },
    },
    select: { answer: true },
  });
  if (!pinned) return null;

  return {
    handle: page.handle,
    displayName: page.displayName,
    question: question.text,
    answer: pinned.answer,
  };
}
```

```tsx
import type { Metadata } from 'next';
import { notFound } from 'next/navigation';
import { serialiseJsonLd } from '@curios/core';
import { getFaqIndex } from '@curios/db-read';
import styles from './faq.module.css';

// Node, not edge: this reads Postgres through the read-only role, like
// /[handle].
export const runtime = 'nodejs';

// FRONTEND.md's "static, revalidate 24h". Deliberately without
// generateStaticParams -- enumerating every qualifying question at build time
// would make `pnpm build` require a live database, which it does not today.
// The first visitor renders; everyone after gets cached HTML.
export const revalidate = 86400;

export async function generateMetadata({
  params,
}: {
  params: Promise<{ handle: string }>;
}): Promise<Metadata> {
  const { handle } = await params;
  const index = await getFaqIndex(handle);
  if (!index) return {};
  return {
    title: `Questions about ${index.displayName}`,
    description: `What people ask ${index.displayName}, answered by ${index.displayName}.`,
  };
}

export default async function FaqIndexPage({
  params,
}: {
  params: Promise<{ handle: string }>;
}) {
  const { handle } = await params;
  const index = await getFaqIndex(handle);

  // An index with no entries is a page with no reason to exist. 404 rather
  // than publish an empty one -- a thin page indexed is worse than no page.
  if (!index || index.entries.length === 0) notFound();

  const jsonLd = serialiseJsonLd({
    '@context': 'https://schema.org',
    '@type': 'FAQPage',
    mainEntity: index.entries.map((entry) => ({
      '@type': 'Question',
      name: entry.question,
      acceptedAnswer: {
        '@type': 'Answer',
        // The index links rather than inlines, so the answer text lives on the
        // entry page. `url` is the honest representation of that.
        url: `/${index.handle}/faq/${entry.slug}`,
      },
    })),
  });

  return (
    <main className={styles.page}>
      <script type="application/ld+json" dangerouslySetInnerHTML={{ __html: jsonLd }} />
      <p className={styles.shop}>{index.displayName}</p>
      <h1 className={styles.heading}>What people ask</h1>
      <ul className={styles.list}>
        {index.entries.map((entry) => (
          <li key={entry.slug}>
            <a className={styles.question} href={`/${index.handle}/faq/${entry.slug}`}>
              {entry.question}
            </a>
          </li>
        ))}
      </ul>
    </main>
  );
}
```

```tsx
import type { Metadata } from 'next';
import { notFound } from 'next/navigation';
import { serialiseJsonLd } from '@curios/core';
import { getFaqEntry } from '@curios/db-read';
import styles from '../faq.module.css';

export const runtime = 'nodejs';
export const revalidate = 86400;

export async function generateMetadata({
  params,
}: {
  params: Promise<{ handle: string; slug: string }>;
}): Promise<Metadata> {
  const { handle, slug } = await params;
  const entry = await getFaqEntry(handle, slug);
  if (!entry) return {};
  return {
    title: `${entry.question} — ${entry.displayName}`,
    // The answer is the description: it is what a searcher wants to see in the
    // result, and it is the owner's own words.
    description: entry.answer.slice(0, 155),
  };
}

export default async function FaqEntryPage({
  params,
}: {
  params: Promise<{ handle: string; slug: string }>;
}) {
  const { handle, slug } = await params;
  const entry = await getFaqEntry(handle, slug);

  // One null for every failure: no such handle, personal page, unpublished
  // page, unknown slug, withdrawn answer. A visitor needs no distinction.
  if (!entry) notFound();

  const jsonLd = serialiseJsonLd({
    '@context': 'https://schema.org',
    '@type': 'FAQPage',
    mainEntity: [
      {
        '@type': 'Question',
        name: entry.question,
        acceptedAnswer: { '@type': 'Answer', text: entry.answer },
      },
    ],
  });

  return (
    <main className={styles.page}>
      <script type="application/ld+json" dangerouslySetInnerHTML={{ __html: jsonLd }} />
      <p className={styles.shop}>{entry.displayName}</p>
      <h1 className={styles.heading}>{entry.question}</h1>
      <p className={styles.answer}>{entry.answer}</p>
      <a className={styles.back} href={`/${entry.handle}`}>
        Back to {entry.displayName}
      </a>
    </main>
  );
}
```

**Three defects this review caught, recorded because they are the shape of what to check

is the only way this class of error is ever found.

**One risk worth naming.** Task 3's collision loop reads the taken slugs and then writes, so two concurrent third-asks on the same page can both read "free". The unique constraint catches it and the loop retries the next name, which is why the write is inside a `try` and why the catch does not inspect the error code. This is not proven by a test — a genuine concurrency test here would need two processes against one row, and slice 5 already spent a task discovering that the connection pool serialises such a pair and makes the test vacuous. The constraint is the guard; the loop is the recovery.
