# Admin, part 1: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a separate admin app where Iman signs in with email and password, sees the Overview, finds a page and suspends it, brings it back, gives a month of Business, resets its conversations, deletes the account or looks at it as the owner (masked), with every action in an audit log.

**Architecture:** a new Next.js app `apps/admin` (port 3002) that, like `apps/web`, reads through `@curios/db-read` (new subpath `@curios/db-read/admin`, read-only role) and writes through the API. The API gets an `admin` module under `/admin/*`, its own session cookie and table, registered only when `ADMIN_ORIGIN` is set. Suspension is enforced where visitors reach a page, in the API and in db-read.

**Tech Stack:** Next.js 15 / React 19, CSS Modules, Fastify 5 + zod, Prisma 6 / Postgres 16, Vitest + Testing Library, BullMQ (mail queue).

**Spec:** `devDocs/admin-design.md` (part 1 and the decisions above it). Look and copy: `design/boards/Admin.dc.html`, `design/screens/Admin_*`. HANDOFF "Admin (Curios team only), 23 Oct 2026".

## Global Constraints

- Copy, colours, spacing and layout from `design/boards/Admin.dc.html`. Every departure gets a row in `design/DEVIATIONS.md` (next free number: 197).
- Admin is English only. Anything visitors or owners see (the unavailable page, the owner's alert, the suspend email) is EN and MS where that surface is bilingual.
- The audit row is written by the API service layer inside the same transaction as the change. No route writes `AdminAction` directly; there is no update or delete for it.
- Every changing action takes `reason` (1–500 chars, trimmed, required). Delete also takes `handle`, which must equal the page's handle.
- Admin sessions: cookie `curios_admin`, httpOnly, SameSite strict, Secure in production, `domain: process.env.COOKIE_DOMAIN`, 8 hours absolute, no sliding refresh. Owner routes ignore it; admin routes ignore `curios_session`.
- Sign-in error for unknown email, wrong password and disabled admin is the same: `Wrong email or password.` (401 `ADMIN_SIGNIN_FAILED`). Run `burnTime()` on the unknown-email path.
- Admin routes are not registered and the CORS list is unchanged when `ADMIN_ORIGIN` is unset; the API must still start.
- Masking in See it as the owner: phone `+60••••••89` (keep country code and last 2 digits), customer and lead names to initials (`Aisyah Rahman` → `A. R.`), conversations as count and times only, no message text, no receipts, no addresses, no emails of customers.
- Migrations hand-written, one folder per task that needs one. Never use the test DB as a shadow DB.
- Never run Prettier over whole files; keep each file's style and line endings.
- Before each commit: `pnpm turbo run typecheck lint test --concurrency=1 --force` (exit status read, never piped; 0 failed, 0 cached) and `NEXT_DIST_DIR=.next-build pnpm --filter @curios/web build` plus `NEXT_DIST_DIR=.next-build pnpm --filter @curios/admin build` once it exists (exit 0), then `git checkout -- apps/web/next-env.d.ts apps/web/tsconfig.json` (and the same two files in `apps/admin` if a build rewrote them). After a migration: `pnpm --filter @curios/db generate`, migrate dev and test DBs (`DATABASE_URL="$(grep '^DATABASE_URL=' .env | cut -d= -f2-)" pnpm --filter @curios/db exec prisma migrate deploy`, and the same with `DATABASE_URL_TEST`), re-run `packages/db/prisma/sql/readonly-role.sql` on both. Never start or stop the dev server.

## Review Focus

1. **A suspended page reached by a path nobody listed** (a FAQ entry URL, the shop item page, `/near`, an order's pay button, a lead posted to an old conversation) must answer as unavailable. Pinned in Task 4 by a test per surface plus a grep step.
2. **An owner session cookie sent to an admin route, or an admin cookie to an owner route,** must be 401 both ways. Pinned in Task 2.
3. **Deleting an account that has payments, a renewal card, orders and a CHIP shop account** must succeed, keep the payments readable (handle and email snapshot) and leave no orphan rows that block it. Pinned in Task 3.
4. **A month granted to a page whose plan already runs to a future date** extends from that date, not from now, and does not count as revenue or paying. Pinned in Tasks 3 and 5.
5. **Two admins (or two tabs) acting on the same page** — suspend twice, bring back a page that is not suspended — answer 409 and write no second audit row. Pinned in Task 3.

  - `POST /admin/pages/:id/unsuspend` — only when suspended; clears both; mails `pageRestoredMail`.

In one transaction: snapshot `pageHandle`/`ownerEmail` onto the page's payments, write the audit row, delete the `Account` (cascades). After it: delete the page's stored files (avatar, cover, QR, item photos, receipts) best-effort through the store, logging failures.
  - `POST /admin/pages/:id/view-as-owner` — writes `VIEWED_AS_OWNER`; 204.
