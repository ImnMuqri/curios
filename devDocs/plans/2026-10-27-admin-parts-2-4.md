# Admin, parts 2 to 4: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the five admin sections part 1 left out. Reports (with the public "Report this page" link), Controls (kill switches, live prices and limits, the owner banner), and AI & usage, Reading sources and Payments (with a CHIP webhook log and Replay). Every change is audited, as in part 1.

**Architecture:** this follows part 1's pattern. The admin app reads through `@curios/db-read/admin` and writes through `/admin/*` routes in `apps/api/src/modules/admin`. The service layer writes each audit row in the same transaction as the change. Controls adds one `SystemSetting` table. `@curios/core` resolves it into a typed `Settings` with defaults, and each process reads it through a 30-second cache: the API and workers via `@curios/db`, the web and admin apps via `@curios/db-read`. Every place that today reads a price, limit or switch reads `Settings` instead. The rule each switch enforces stays in its own module (chat in chat, sign-up in auth, and so on), never in admin.

**Tech Stack:** Next.js 15 / React 19, CSS Modules, Fastify 5 + zod, Prisma 6 / Postgres 16, BullMQ, Vitest + Testing Library.

**Spec:** `devDocs/admin-design.md`: "Part 2: Reports", "Part 3: Controls", "Part 4: AI & usage, Reading sources, Payments", plus the decisions above them. Look and copy: `design/boards/Admin.dc.html` (sections `AI & USAGE`, `JOBS`, `MONEY`, `REPORTS`, `CONTROLS`, and the data at lines ~495–700) and `design/screens/Admin_{ai,jobs,money,reports,controls}_1440.png`. The part 1 plan (`devDocs/plans/2026-10-23-admin-part-1.md`) shows the established shapes.

## Builder's calls in this plan (Iman can overrule)

1. **Report reasons** (no board draws the form): `SCAM` "Looks like a scam" / "Nampak macam penipuan", `IMPERSONATION` "Pretending to be someone" / "Menyamar sebagai orang lain", `WRONG_PRICES` "Wrong prices or details" / "Harga atau butiran salah", `OFFENSIVE` "Offensive" / "Menyinggung", `OTHER` "Something else" / "Lain-lain". The first two match the board's sample rows.
2. **Flagged** means more than 5 open reports, so 6 or more. Nothing is hidden automatically. The board's note becomes: "Visitors report a page from the “Report this page” link in its footer. Nothing happens to a page until you act."
3. **Reports are grouped by page**, one row per page, as the board's "4 reports · today" shows. Dismiss, Email owner and Suspend act on all of that page's open reports at once.
4. **"Emails to owners" off means stop, not hold** (the spec decides behaviour). The board's line changes to "Off: emails to owners are not sent. Sign-in and password emails still go." Admin's own mails (suspend, bring back, report warning) always go, because the admin chose to send them.
5. **"Reading new sources" and "Pause the queue" are one state.** Off pauses the BullMQ ingest queue: owners can still add sources, and those wait. Owner re-reads and admin retries are refused while it is off.
6. **CHIP off** copy becomes "Off: checkouts offer only the owner’s own QR or bank transfer."
7. **The web reads settings per request through `@curios/db-read`**, not over HTTP from the API. The landing and legal pages get `revalidate = 30`, so a price change reaches them within 30 seconds, matching the API's cache. If the database can't be reached, `getSettings()` falls back to the defaults, so a build without a database still succeeds.
8. **Payments' "Paid by"** is stored from now on (`Payment.paidVia`, from CHIP's purchase) and reads "—" for older rows. The "Refunded" figure is left out, because no refund is recorded anywhere.
9. **"I'm not sure" answers** show the visitor's question and the page, but not the reply (the spec's "no transcripts"). The cost-by-job table has three jobs, Answering visitors, Reading sources into facts and Grouping questions, because embeddings and lead summaries write no `ModelCall` rows.
10. **The webhook log** records CHIP's callback and webhook messages, one row per (source, purchase, event), with attempts counted. Replay re-runs the stored body through the same handler, without re-checking a signature that already passed when the row was stored.

## Review Focus

1. **A price changed in Controls must match what CHIP is asked to charge**, everywhere: checkout, auto-renew, the reminder mail, Billing, landing, Terms. Task 9 pins it with a test that saves a new price and reads it back through each surface's function, plus a grep for any remaining `PLAN_PRICES_CENTS`/`FREE_LEADS`/`FREE_ORDERS` read outside the defaults.
2. **A switch turned off has to hold on the paths nobody listed.** Covered paths: chat test mode for chat off, Google sign-up for sign-ups off, owner re-reads for reading off, auto-renew and shop pay-online for CHIP off. Task 8 has a test for each.
3. **A malformed or missing `SystemSetting` row must never take Curios down.** Bad JSON, a negative cap or a text price all fall back to that key's default and log a warning. Task 6 tests this.
4. **The public report form will be abused:** a flood from one IP, details over 500 characters, reports against a suspended, unpublished or missing page. These answer 429, 400, 404 and 404, store nothing, and keep the IP out of the record. Task 2.
5. **Replaying a webhook that already granted** must not extend `paidUntil` a second time. The handler is idempotent and replay goes through it. Task 13 tests it.

  - `defaultSettings(): Settings`: every switch on; `cap: conversationCap()`; `FREE_LEADS`, `FREE_ORDERS`, `PLAN_PRICES_CENTS`; no banner. The constants stay as the defaults.

  - `BANNER_MAX = 160`, `PRICE_MAX_RM = 999`.
  - `isBigPriceChange(oldCents: number, newCents: number): boolean`: true when new > RM999 or |new − old| > old / 2.
- `@curios/db`: `createSettingsReader(prisma, { ttlMs = 30_000, log? }): { get(): Promise<Settings>; clear(): void }`. Concurrent `get`s share one query. A failed query keeps serving the last good value, or the defaults if there is none, and logs.
- `@curios/db-read`: `getSettings(): Promise<Settings>`, the same cache over `prismaRead` (30 s), with the same fallback to defaults on error (builder's call 7).
